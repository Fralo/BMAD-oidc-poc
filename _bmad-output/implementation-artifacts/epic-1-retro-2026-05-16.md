## What went well

### 1. The deferred-work.md ledger was the spine of cross-story coordination

53 findings (D1–D53), each tagged with surfacing story, owning story, severity, and an explicit `Resolution (date, story)` marker when closed. Examples:

- D2 (browser↔container hostname) surfaced in Story 1.1, partially closed in 1.2 (audience mapper half), fully closed in 1.5 (`OIDC_AUTHORIZE_URL_BROWSER` two-URL split).
- D33 (open-redirect `return_to` validation) surfaced in Story 1.4 model layer, closed in 1.5 with `safe_return_to(raw)` + 13 parametrized tests.
- D40 (state/nonce PK collision) surfaced in 1.4, closed in 1.5 with 3-retry-then-raise in `SessionService.create_*`.
- D45 (`/health` issuer probe wrong post two-URL split) surfaced in 1.11, fixed inline with new health-probe contract.
- D46 (SPA not served — AR24 orphaned) surfaced in 1.13, closed in Story 1.14.

Nothing got dropped. The ledger drove forward-discipline across stories.

### 2. Cross-story leakage was near-zero thanks to "What this story is — and is not"

Every story spec carried a Dev Notes section listing what was explicitly out of scope and an "Anti-patterns to avoid" section. Story 1.5 set the `csrf_token` cookie at callback time but did NOT add CSRF middleware — that waited for 1.6. Story 1.5 didn't touch logout (1.7's territory). The discipline kept stories merge-clean.

### 3. The synthetic-IdP test harness in Story 1.5 was a force multiplier

`tests/auth/synthetic_idp.py` — in-process RSA-2048 keypair, respx-mocked `/authorize`/`/token`/`/revocation`/`/end_session`/JWKS routes, `make_id_token(claims_override=…)` for negative-path variants — enabled 67 new auth tests in 1.5 alone, and was reused by Stories 1.7 (logout revocation), 1.12 (test-reset), 1.13 (E2E). One harness, four consumers.

### 4. Pre-implementation scope cut was textbook

The 2026-05-14 observability stack removal (`/bmad-correct-course`) executed before any story had started. Four containers, two env vars, AR29, and Smoke steps 14–15 dropped cleanly. Story 1.1 began with the post-cut scope. Zero rollback cost.

### 5. 3-layer adversarial code review moved real work

Blind Hunter + Edge Case Hunter + Acceptance Auditor on every story. Concrete output volumes:
- Story 1.5: 14 patches applied + 6 defers logged.
- Story 1.7: 9 patches applied + 5 defers logged.
- Story 1.13: 3 patches applied + 6 defers logged.

Patches landed in-story; defers landed in `deferred-work.md`. The review wasn't ceremony — it was where real bug fixes happened.

### 6. Gates held green through 14 stories

`ruff check` / `ruff format --check` / `ty check` / `pytest --cov` / `docker compose config` / `docker compose build` — every gate green at every story's close. BFF coverage rode at 96–98% throughout. The archetype's `fail_under=90` enforcement caught coverage drift twice.

## What was hard

### 1. AR24 was orphaned in the original epic decomposition (D46)

Architecture line 84 mandated "BFF's multi-stage Dockerfile compiles SPA in a Node stage and copies `dist/spa/browser` into the BFF image; BFF mounts it at `/` with HTML5 history fallback." Story 1.8 was scaffold-only. Stories 1.9 and 1.10 added SPA code. *No story owned the SPA-serving path.*

The gap was invisible until Story 1.13's Playwright tried to navigate to `http://bff:8000/login` and got a 404. Story 1.14 was added mid-epic to close it — a clean recovery, but the discovery cost a full live-stack debug cycle in 1.13.

**Root cause:** the original epic-to-AR mapping wasn't traceable. AR24 had no owner story.

### 2. Browser↔container hostname split (D2/D8/D45) took three stories to settle

The topology — Keycloak running with `KC_HOSTNAME=localhost` for browser correctness, but BFF using `keycloak:8080` for back-channel token exchange — couldn't be fully resolved until both sides existed. Story 1.2 closed the audience-mapper half. Story 1.5 introduced `OIDC_AUTHORIZE_URL_BROWSER` for the two-URL config. Story 1.11 then surfaced D45 because `/health` still used the old single-URL assumption.

Each fix was correct in isolation. The cumulative topology only became visible incrementally.

### 3. Archetype-vs-architecture path discrepancies cost dev cycles

Architecture says `db/models/`; archetype emits `models/entities/`. Architecture and archetype disagreed about synthetic-IdP location. Each story had to make a coherence call inline. Story 1.4's Dev Notes literally has a section titled "🚨 Path discrepancy: `db/models/` (architecture) vs `models/entities/` (archetype reality)."

### 4. Archetype accommodation tax recurs every install

Story 1.3 had to fix the archetype's `--no-demo` script leaving dangling `dummy` imports. Coverage initially landed at 83% because `auth/entra.py` (Azure AD bearer validation, 151 LOC, unreachable in our cookie-session design) had to be added to `[tool.coverage.run].omit` with a documenting comment. The archetype's OTEL/Prometheus modules boot but emit nothing post-cut. Each install pays the same three accommodations.

Story 3.1 (Resource Server) will pay this again unless the pattern is documented.

### 5. D3 (placeholder-credentials fail-fast) partial closure

Story 1.12 closed `TEST_RESET_TOKEN`. Story 1.13 closed `BFF_CLIENT_SECRET`. The `KEYCLOAK_ADMIN_PASSWORD` half is still deferred with no natural owner story before Epic 5.

### 6. Compose-driven ACs were fragile to upstream gaps

Story 1.11 AC8 (compose `--profile e2e up --abort-on-container-exit` exits 0) blocked by D45 until fix. Story 1.13 AC6 (`just e2e-up` with passing specs) blocked by D46 until 1.14. Static gates always passed in each story; only the live-stack ACs failed. The pattern: when a story's success depends on the compose stack actually running, static gates aren't enough.

### 7. /health, written in Story 1.3, froze the pre-1.5 auth topology

When Story 1.5 added the two-URL OIDC split, the health probe's issuer check became wrong — but nobody walked upstream to verify. D45 surfaced as a result.

## Action items

### Process improvements

**P1 — AR-to-story traceability matrix before Epic 2 kickoff** _(CRITICAL PATH)_
Walk every AR1–AR34 (minus deleted observability AR29) and map each to the owning Epic 2 story (or earlier if cross-epic). Flag any AR not owned. Prevents another D46.
- Owner: **Winston (Architect)**
- Deadline: before Story 2.1 starts
- Success: matrix file lives in `_bmad-output/planning-artifacts/`; every AR has either an explicit story owner or a "deferred to Epic N" annotation

**P2 — Compose-stack ACs run live or are explicitly downgraded**
If a story has an AC that depends on `docker compose ... up`, the story does NOT close to `done` until either (a) the live run succeeded, or (b) the AC is explicitly downgraded with a tracking entry referencing the blocker.
- Owner: **Amelia (Developer)** (process enforcement at code-review time)
- Deadline: applied from Story 2.7 (J2 E2E spec) onward
- Success: added as an explicit checklist item in the story-completion template

**P3 — When a downstream story changes shared topology, walk upstream**
When auth URLs / health probe semantics / cookie attributes / discovery flow changes, the dev agent walks upstream callers and re-checks. D45 would not have surfaced as a blocker if 1.5's split had triggered a /health audit.
- Owner: dev agent (checklist item added to story Dev Notes template)
- Success: template updated before Story 2.1
