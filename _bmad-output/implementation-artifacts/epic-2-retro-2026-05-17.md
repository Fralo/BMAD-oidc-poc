## What went well

### 1. The "epic-doc paths vs. codebase" translation discipline carried Epic 1 → Epic 2 cleanly

Zero churn from path-discrepancy confusion in dev or review. The pattern is load-bearing knowledge — see A3 below.

### 2. Signal-based SPA architecture stacked beautifully across Stories 2.4 → 2.5 → 2.6

- Story 2.4's `BooksService` (signals + `inject(...)` DI per AR4 / AR23) followed `AuthService`'s shape verbatim — no surprises.
- Story 2.5's `BookForm` authored as `variant='add'`.
- Story 2.6 *extended* `BookForm` to `variant='edit'` with **zero `BooksService` modifications** and 9 new edit-variant tests. The signal contract held.

The optimistic-UI implementation (`setStatus` snapshot → optimistic update → PATCH → confirm-or-revert) is a textbook example of UX-DR7 made testable.

### 3. The optimistic-UI Playwright idiom is a reusable pattern

Story 2.7's J2 spec proves optimistic-before-network via `page.route` holding the PATCH open with a developer-controlled Promise, asserting on-screen state *before* releasing the response. From the Dev Notes:

> "the deterministic Playwright idiom for proving optimistic-before-network — pure timing-based races are flaky against sub-millisecond local stacks."

Worth lifting into the e2e helpers when the same shape recurs (Epic 3 `SettingsView` already merged with similar saving-state UI).

### 4. Cross-user isolation: 404-not-403 with SQL-composed predicate

Story 2.2 hit security posture exactly: the SQL `WHERE id = :id AND sub = :sub` composes both predicates in one query, producing 404 `book_not_found` whether the row doesn't exist or belongs to another user. The story spec was explicit about the *why* ("existence is not leaked across users"); the dev agent quoted it back in Dev Notes. Spec → implementation traceability worked.

### 5. Three-layer adversarial review pattern matured

Totals across the epic: **1 must-fix + 3 should-fix + 21 defers logged + 14+ dismissed**. Story 2.7 closed with zero must-fix, zero should-fix. The review didn't go ceremonial — it shifted from Epic 1's *"find bugs and fix them in-story"* to *"separate must-fix from defer-with-rationale"*. ## What was hard

### 1. W9 — The `just e2e-up` compose-runner saga (the only real bruise)

Story 2.7 AC13 required `docker compose --profile e2e up --abort-on-container-exit` to exit 0 with all J2 specs passing. Empirically: **1 passed / 12 timed out** in a 12.5-minute run.

**Root cause:** Keycloak's `KC_HOSTNAME=localhost` emits browser-facing URLs anchored on `localhost:8080`. Host-side dev works (Keycloak's port is published to the host). Inside the `playwright` compose-runner container, **Chromium hard-codes `localhost` to its own loopback** as a security/performance special-case — `/etc/hosts` entries for `localhost` are ignored regardless of `extra_hosts: ["localhost:host-gateway"]` overrides.

**Post-Story-2.7 follow-up (commit `d7d8526`)** tried:

- **Option (a)** — `extra_hosts: ["localhost:host-gateway"]` — failed (Chrome ignored the hosts entry).
- **(a)-variant via `host.docker.internal`** — got the browser past the initial KC redirect (login form rendered, password submitted, KC's *non-secure context* cookie warning confirmed in logs) but failed at the next step: KC's post-login 302 back to the BFF callback landed on `chrome-error://chromewebdata/`. The partial fix only covered 2 of the **4 URLs** that need to be browser-reachable from inside the runner.

**The full URL chain** (now documented in `deferred-work.md` W9):

1. KC authorize endpoint (`OIDC_AUTHORIZE_URL_BROWSER`)
2. KC login form + session cookies (`KC_HOSTNAME`)
3. BFF callback URL (`BFF_BASE_URL` → `/auth/callback`)
4. Playwright `baseURL` (`E2E_BASE_URL`)
5. KC realm `redirectUris` + `webOrigins`

**Validation cost so far:** two ~13-minute compose runs (each times out 12 × 60s). Lesson learned: debug with a single-test invocation once a hypothesis is wired; full-suite runs are too expensive for blind iteration.

**Upstream gap:** the bug traces to Story 1.14 AC8 — *"Live `just e2e-up` skipped — requires running Keycloak + full compose stack. Deferred to reviewer."* No subsequent story closed the loop. Epic 1 retro's **P2** ("Compose-stack ACs run live or are explicitly downgraded") was framed as *"applied from Story 2.7 onward"*, which was exactly too late for the 1.14 surface that created the gap.

**P2 honored honestly in 2.7:** the local-dev workflow runs in 11.9s with 8/8 J2 green; the deferral was documented with a comprehensive post-mortem in W9. So the rule held — but the gap it was meant to prevent had already opened.

### 2. D64 / D65 — Stale E2E assertions (the regression canary)

When SPA surface changed in Stories 2.5 (placeholder swap) and 1.10 late-patches (LoginView heading), the *existing* J1/J5 E2E specs silently broke:

- **D64** — Story 1.13's J1 spec asserted `getByText('Books — coming in Epic 2')` against the placeholder text. Story 2.5 replaced the placeholder with the real `BookListPage`. Story 2.5 + 2.6 did not run the J1 spec; surfaced in Story 2.7's full-suite run.
- **D65** — Story 1.13's J5 spec asserted `getByText('Reading Time Estimator')` which became ambiguous after Story 1.10's late patch added `<h1>Sign in to Reading Time Estimator</h1>` (matched both the top-chrome brand and the LoginView heading).

Both are two-line fixes; both closed in the 2.7-follow-up commit `d7d8526`.

**The pattern:** when SPA surface changes, the E2E suite is the canary, and we don't run the canary unless the story explicitly says "E2E". Worth a process touchpoint — see A3 area.

### 3. The concurrency-defer cluster (five items in one epic)

Five separate defers across Stories 2.4 / 2.5 / 2.6 all about in-flight guards on the signal-based reactive layer:

- **D54** — `BooksService.setStatus` snapshot races on concurrent calls (revert restores intermediate optimistic value, not original).
- **D55** — `BooksService.load()` last-wins on concurrent calls (no in-flight de-dup).
- **D56** — `BooksService.update()` against unknown id triggers phantom signal write (new array reference even when no row matched).
- **D58** — `BookForm.onSubmit` has no synchronous double-submit guard beyond DOM `[disabled]` (programmatic callers race).
- **D62** — `BookRow.onDeleteClick` has no in-flight guard (double-click dispatches two DELETE requests; second 404s with misleading "Couldn't delete" copy on an already-gone row).

Each item is low-severity in isolation. Together they suggest the signal-based architecture has a *category* the spec authors keep deferring. **Decision:** bundle into a single Epic 5 hardening story — see A2.

### 4. Small process scars (fast-surface, fast-resolve)

- **Story 2.6 output naming collision with native DOM events.** Spec called for `save` / `cancel` outputs; `@angular-eslint/no-output-native` blocked both (collisions with `Window.save` and `HTMLDialogElement.cancel`). Renamed to `bookSaved` / `editCancelled`. **Lesson:** spec authoring should run forward the SPA's eslint config when proposing output names.
- **Story 2.2's `PATCH {"title": null}` → 500 IntegrityError fall-through (W5).** Explicitly accepted in spec Dev Notes as "future hardening." Ugly footgun for any client passing explicit nulls, but no observed user path triggers it.
- **Defer ledger growth — W7/W8 in Story 2.3 are *coverage-symmetry* defers**, not behavior gaps. Honest classification, but the ledger is becoming a mix of load-bearing and nice-to-have items. Epic 5's security review (Story 5.2) is the right owner for a reclassification pass.

## Key takeaways

1. **Patterns from Epic 1 held — but the retro commitments mostly didn't matter.** Five of six Epic 1 action items went unaddressed; Epic 2 still shipped clean. The lesson is calibration: retros learn what's load-bearing. Drop unactioned items rather than re-committing them.
2. **W9 is the one real scar.** The compose-runner OAuth chain is broader than any single story owned, and Story 1.14 AC8's "deferred to reviewer" never got re-owned. Fix it via a dedicated story (A1).
3. **The signal-based reactive layer has a deferred concurrency category.** D54/D55/D56/D58/D62 are individually low-severity but they cluster. Single Epic 5 hardening story addresses the whole class (A2).
4. **Worktree-per-story + cross-epic parallelization is the new normal.** Stories 2.4–2.7 ran in parallel against shifting HEADs; Epic 3 stories 3.3–3.5 merged onto `epic-2` ahead of Epic 2's own close. `sprint-status.yaml` lags `git`; treat `git log` as source of truth.
5. **E2E suite is the SPA-surface regression canary.** Stories that change SPA copy or DOM shape must re-run the E2E suite even when their own ACs don't say "E2E." D64/D65 surfaced precisely because Stories 2.5 and 2.6 didn't.
