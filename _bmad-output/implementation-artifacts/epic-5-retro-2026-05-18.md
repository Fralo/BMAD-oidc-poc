## What was hard

### 1. D142 — security review attestation diverges from default-profile reality (medium-to-high)

**The standout finding.** Story 5.2's §5 attests that "scope enforcement is enforced at the RS." True under `--profile e2e` (which the e2e overlay activates via `compose/app.e2e.yml:53`'s `AUTH_TYPE: oidc_bearer`). **False under `--profile default`** — the canonical prod-shaped bring-up the smoke targets. `services/resource-server/.env.example:57` has `#AUTH_TYPE=oidc_bearer` commented out; the RS runs in archetype synthetic-admin mode; JWT signature / scope / iss / aud are not validated.

The smoke ran with a `sed -i.bak` workaround flipping the flag. The Run Record attests AUTH_TYPE=oidc_bearer state, not default-profile-as-shipped state — documented honestly in D142 + the Run Record.

**The doc and the running system disagree on a security claim.** This is the kind of finding that, in a non-educational project, would block release. For BMAD_books, Nearformer's call is **fast-follow fix before handoff** (see A2 below).

### 2. D140 + D141 — README quickstart is broken on this host

- **D140** — bare `docker compose up` exits with `no service selected` on Compose v5.1.3 + Docker 29.4.3. Canonical working form is `docker compose --profile default up --build`. README + architecture + epic AC all carry the stale form. The smoke surfaced this empirically; Story 5.3's README polish at line 162 made a counter-claim ("default profile activates automatically") that contradicts observed behavior.
- **D141** — per-service `.env` files (`services/bff/.env`, `services/resource-server/.env`) required in addition to repo-root `.env`. First-time operator following README step 3 gets `env file ../services/bff/.env not found`.

Both are doc-vs-code drifts the README polish missed because Story 5.3 didn't run the bring-up.

### 3. Story 5.2's 7 fabricated D-IDs

The most concrete instance of the citation-fabrication failure mode. The story's first dev pass wrote a Known-Gaps subsection citing D369, D371, D372, D440, D441, D442, D470 — none of which existed in `deferred-work.md` (max actual: D135). 37% of Known-Gaps citations had no resolvable target. Caught at code review; resolved by backfilling the 7 D-entries to make the citations resolve (rather than rewriting the doc to remove them).

**Implication:** doc-only stories that cite a registry need a pre-review check that every cited ID resolves. The adversarial review caught it; an automated pre-check would have caught it earlier.

### 4. Mode-B partial smoke leaves 8 operator-pending steps

Steps 6-13 (J1/J2/J3/J4/J5/J6 browser walk-throughs) remain `[ ]` PENDING-operator. The Operator follow-up checklist names exactly what a human-with-browser needs to do.

The smoke artifact is solid on what it attests; honest about what it doesn't. **Verdict: PASS WITH ANOMALIES.** Full PASS requires operator walkthrough.

## Key takeaways

1. **Doc-only epics need full adversarial review.** Citation fabrication, factual misclaims, and source-line drift are LLM failure modes the review reliably catches. 44 patches in one doc-only epic is the proof point.
2. **The smoke is the project's reality check.** It found three doc-vs-code drifts (D140-D142) that the docs themselves could not see. D142 in particular — security review attests scope enforcement; default-profile bring-up doesn't enforce it — is the kind of gap that only a live bring-up surfaces.
3. **Mode-A/Mode-B smoke split is a pattern worth keeping.** When the agent lacks a desktop browser, Mode B (programmatic bring-up + HTTP probes + Operator follow-up checklist) is honest about what it attests vs. what requires a human. Mode A is the canonical happy path.
4. **`[[no-ceremony-action-items]]` is load-bearing.** Three Epic-2 commitments unaddressed; project shipped clean anyway; all three dropped here without re-committing. The memory note saved us a carryover list that would have masked which actions matter.
5. **Parallel-epic execution scales to project close.** 4 stories in one day, no scope drift, no leakage. The worktree-per-story pattern + the failure-prevention discipline are the load-bearing process artifacts of this project.
